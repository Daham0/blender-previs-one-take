# 07 验收清单与踩坑库

## A. 阶段关卡（六阶段流程，不通过不许进下一阶段）

| 关卡 | 检查 | 不通过的表现 |
|---|---|---|
| 关 0 入口 | 用户已给参考图或描述；3 句话复述得到确认；画幅时长明确 | 用户不知道接下来会发生什么 |
| 关 1 路线 | `check_blender.py` 跑过；路线 A/B 已选定并告知用户 | 没探测就搭场景，装不装靠猜 |
| 关 2 首版白模视频 | 有能播放的视频 + 3–4 张关键帧交付给用户 | 只丢坐标表/截图，用户看不到镜头 |
| 关 3 迭代 | 每版新编号 + 1 行变更说明；只改用户提到的那一项 | 一次改五项，用户判断不出因果 |
| 关 4 定稿校验 | 四项校验 `RESULT: PASS` | 带 FAIL 去写词，成片必穿模 |
| 关 5 写词 | 六栏目齐全，坐标全部来自实测 JSON | 手填估算坐标 |
| 关 6 出片交付 | 白模标注运动参考、参考图标注画面参考、首句强调复刻 | 模型把白模灰模质感带进成片 |

## B. 定稿内部关卡（阶段 ⑤ 逐项验收）

### 关 1：场景
- [ ] 1 单位 = 1 米，原点在地面
- [ ] 坐标清单落盘（md 或 csv）
- [ ] 同机位对照图 + 正交俯视 + 正交正视三张图齐全
- [ ] 前景 / 中景 / 远景三层都有物件

### 关 2：轨迹
- [ ] 极角一阶差分符号全程不变（无折返）
- [ ] 机位高、半径单调
- [ ] 俯视轨迹图已目视确认
- [ ] 仰角有意图且不跨越 0° 反复翻越

### 关 3：预演
- [ ] 低采样 480P / 960×540 出片，无黑帧
- [ ] 逐帧 NDC 主体在 [0.02, 0.98] 内，出画帧数 = 0
- [ ] 运动组两两穿模对数 = 0
- [ ] 所有物体最高点 ≤ 层高 − 0.1 m
- [ ] 房间墙体 / 地板 / 窗全程静止
- [ ] 关键帧静帧齐全（首帧、各起飞点、收束帧）

### 关 4：数据
- [ ] 逐帧 JSON 落盘，含 cam、注视点、仰角、半径、极角、各物体中心
- [ ] 抽查 3 帧人工比对画面与坐标一致

### 关 5：提示词
- [ ] 六栏目齐全
- [ ] 每段都有"起止机位 + 注视点 + 仰角 + 半径"
- [ ] 坐标全部来自实测 JSON，无手填估算
- [ ] 声明"白模只锁运动、不作画面参考"
- [ ] 声明唯一运镜方向 + 禁止折返
- [ ] 分层时序写成因果句
- [ ] 反向提示词覆盖七类风险
- [ ] 时长与平台上限匹配（5s / 10s / 更长需隐切或拆分）

### 关 6：交付
- [ ] 预演视频 + 提示词 + 关键帧一并交付
- [ ] 说明"预演只校验运动，画面以参考图为准"
- [ ] 工程文件与产物落在项目盘，未写系统盘

## 踩坑库（均为实际项目发生）

| 编号 | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| P01 | 先写提示词后建场景 | 坐标靠估、运镜鬼畜、场景走样 | 流程固定：建场景 → 定轨迹 → 预演校验 → 写词 |
| P02 | 用白模预演当画面参考 | 成片灰模感、造型跑偏 | 画面只认参考图；白模只锁运动 |
| P03 | 手 K 关键帧导致曲线回弹 | 镜头左右反复（鬼畜） | 参数化 + 极角单调 + 一阶差分校验 |
| P04 | 主体升空镜头不跟随 | 人物出画 | camz/lookz 跟随系数 0.8–0.95 |
| P05 | 人与椅同时起飞 | 腿/扶手穿模 | 人先飞、椅延后 0.4–0.7s |
| P06 | 椅子直接上浮 | 与腿部干涉 | 椅子先水平后退 0.3–0.5 m 再升空 |
| P07 | 桌面设备与桌体同时起飞 | 设备与桌面相撞 | 设备先升起 1.3 m 悬停，桌体延后 2–3 s |
| P08 | 键鼠与人手不同步 | 手穿键鼠 | 键鼠独立组，z 与手部同步 |
| P09 | 房间跟着悬浮 | 悬浮感消失、空间参照丢失 | 只对主体组做 z 位移，墙地窗不动 |
| P10 | 提示词未锁人物朝向 | 生成时人物转身、正脸崩坏 | 【参考】写死背向/侧背向；【反向】加转身回头 |
| P11 | 用"注意不要穿模"这类否定句 | 模型反而更容易出穿模 | 用因果句描述顺序与间隙 |
| P12 | 时长与节奏不匹配 | 动作平铺、收尾仓促 | 三段式节奏 + 收尾 0.4–0.6s 减速静止 |
| P13 | 便携版未建 portable 目录 | 配置写进 %APPDATA%，C 盘占用 | exe 同级建 portable 空目录 |
| P14 | 进度式渲染一次出成品 | 时间长、返工成本高 | 先关键帧静帧 → 再 480P 低采样预演 → 确认后出片 |
| P15 | 文件教程名带标点（如 v1.0） | 不符合部分平台命名规范 | 名称禁标点，用 `v10` 之类纯字母数字 |

### 踩坑库第二批（脚本化过程中实测）

| 编号 | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| P16 | 用 `world.node_tree.nodes["Background"]` 取世界背景节点 | Blender 4.5 抛 KeyError，场景只生成一半 | 按 `n.type == "BACKGROUND"` 遍历查找；没有就新建 `ShaderNodeBackground` 并连到 `OUTPUT_WORLD` |
| P17 | 只写官方 `download.blender.org` 下载地址 | 部分网络直接 403，安装引导卡死 | 脚本按 官方 → 阿里云 → 清华 的顺序自动回退；实测阿里云可取到 4.5.16（约 380MB） |
| P18 | 相机没做 look_at，就用默认朝向渲染 | 240 帧全部主体出画（NDC 出画率 100%） | 建相机后立即 `(target - cam.location).to_track_quat("-Z","Y")` 定朝向，再做轨迹 |
| P19 | 环绕圆心沿用了别的项目坐标 | 圆心没落在主体上，20mm 广角下大面积出画 | `--center` 必须与主体所在世界坐标一致；换项目就重设 |
| P20 | 穿模检测不分组、不算基线 | 桌腿贴桌面、椅座贴椅柱全部误报（实测 4560 对） | 按对象名首段分组、同组忽略；跨组用"首帧重叠深度 + 0.05m 容差"判增量 |
| P21 | 竖屏升幅照抄 1.27m，层高只有 2.75m | 顶面 2.765m 顶穿天花板（130 帧违规） | 升幅按"物体顶面 ≤ 层高 − 0.1m"反算；模板竖屏取 1.12 |
| P22 | NDC 检测把椅子等低位附属物也算进去 | 收尾时椅座必然压到画面下沿（17 帧出画） | NDC 只填主体关键点（头、躯干、桌面、主屏）；附属物单独评估 |
| P23 | Windows 下用默认编码捕获 Blender 输出 | `UnicodeDecodeError: gbk` 导致整个校验流程中断 | `subprocess.run(..., encoding="utf-8", errors="replace")` |
| P24 | 逐帧 K 帧后不设插值 | 默认 BEZIER 在首尾过冲，镜头起步/收尾轻微回弹 | 关键帧写入后统一把 `keyframe_points[].interpolation` 设为 `LINEAR` |
| P25 | 逐帧校验脚本把"所有运动物体"两两组合 | 40+ 物体两两组合，单帧上千对，240 帧跑十分钟 | 只在指定前缀集合内组合，先按组过滤再算 AABB |
| P26 | 渲染测试就跑满 240 帧 | 单次验证代价过高 | 先 `--start 1 --end 16` 出小样验证管线，再跑全片 |

### 踩坑库第三批（流程层，决定用户是否用得下去）

| 编号 | 坑 | 后果 | 正确做法 |
|---|---|---|---|
| P27 | 首版没出视频就写提示词 | 用户没看过镜头，词写得再准也是废稿 | 先把白模视频交出去，得到"就是这个感觉"再动笔 |
| P28 | 向用户解释极角 / NDC / 穿模对数 | 用户听不懂，把零门槛工具当成技术门槛 | 只讲"绕多远、飞多高、会不会撞"；参数留在内部 |
| P29 | 参考视频没写清角色 | 模型把白模的灰模质感、块面造型带进成片 | 提示词写死"视频1=运动参考，不参考画面质感与造型" |
| P30 | 开工前一次抛 5 个问题 | 沟通成本高，用户直接流失 | 最多 3 个必问项，其余默认值先出第一版让他挑毛病 |
| P31 | 白模时长与目标成片不一致 | 成片节奏被模型自行删改，运镜被压缩 | 白模时长 = 目标时长（5s / 10s） |
| P32 | 迭代时覆盖同名文件 | 分不清哪版是定稿，回不到上一版 | `v1/v2/v3` 编号 + 变更说明，命名禁点号 |
