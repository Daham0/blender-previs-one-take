# 00 入口、对话式迭代与出片对接

本文件定义本技能的**对外运行方式**：用户在什么位置接入、以什么颗粒度提修改、最终怎么和视频模型接上。所有脚本与规范都在这个流程之下服务。

## 1. 用户只需要提供两样东西（任选其一即可启动）

| 输入 | 例子 | 处理 |
|---|---|---|
| 参考图（1 张） | 场景照片、竞品画面、分镜图、情绪板 | 从图里读空间关系（层高、家具相对位置、主体朝向、光源方向），搭同构白模 |
| 描述（一句话） | "10 秒，从我背后横着绕半圈到侧前方，桌上的东西先飘起来" | 按描述搭白模；缺的细节用同类场景默认值补 |
| 图 + 描述 | 最常见 | 图定画面与空间，描述定运镜与时序 |

**不要等用户给齐参数。** 用户给不出"极角 186°→300°、半径 3.45→2.45m"这种数据，这是本技能内部工作，不是输入条件。

## 2. 最少必问项（能推断就不问；必须问时一次性问完，最多 3 个）

1. **时长 + 画幅**：默认 10s、横屏 16:9（口播/广告投放可维持默认）。
2. **主体与朝向**：人 / 产品 / 空空间；人在画面里是否露脸（默认全程背向、不回头）。
3. **运镜意图**：环绕 / 前推 / 升空跟随 / FPV 穿梭。用户说不清时，给出两个方案各一句话让他选，不要让他描述技术细节。

其余（层高、机位、半径、失重顺序）全部由你按 `knowledge/kb-levitation-office.md` 的模板推算。

## 3. 六阶段对话节奏（每阶段只让用户做一件事）

| 阶段 | 你交付给用户的东西 | 用户要做的事 | 话术要点 |
|---|---|---|---|
| ① 接需求 | 3 句话复述"我理解的一幕" + 确认画幅时长 | 说"对"或改一句 | 复述里要含主体、运镜方向、有没有失重/漂浮 |
| ② 探环境 | 一句话说明走哪条路（Blender 高精度 / 装便携版 / 网页白模） | 二选一 | 只给一个决策点，见 SKILL.md §3 |
| ③ 首版白模视频 | **能播放的视频** + 3–4 张关键帧 + 一句"哪里不对直接说" | 看片，提意见 | 必须真的出片。只给坐标表和截图 = 违约 |
| ④ 迭代 | 新版本视频 `v2/v3…` + 1 行变更说明 | 用大白话继续提 | 每轮只改他提到的那一项 |
| ⑤ 定稿 + 写词 | 四项校验结果 + 六栏目提示词 | 确认"就是这个感觉" | 校验没过不给词 |
| ⑥ 出片 | 白模视频 + 提示词 + 上传口径 | 丢给 Seedance 2.5 | 见本文件 §6 |

阶段 ③④ 可以来回多轮，**这是本技能的主体价值**：把运镜问题在 3D 里改掉，而不是在视频模型里抽卡。

## 4. 大白话 → 参数翻译表

用户只会说感觉，你必须翻译成参数并只改这一项。

| 用户说 | 改什么 | 注意 |
|---|---|---|
| 太远了 / 离近点 | 半径 `r0 r1` 同步 −0.3~0.6m | 前推镜头只改末端 r1 |
| 再高点 / 想俯视一点 | 机位高 `z` 整体抬，或注视点下移 | 抬机位要同步校验穿顶 |
| 有点仰 / 别仰拍 | 注视点抬高或机位降低 | 仰角跨 0° 反复会抖 |
| 转太快了 | 时长不变时减小 `a1−a0`；或加时长 | 减速优先加时长，别硬拉跨度 |
| 绕得不够 / 多转点 | `a1−a0` 加 20°~40° | 跨度加大后必查主体是否出画 |
| 东西飘得太早 | 失重起始帧整体后移 0.3~0.8s | 整体后移，别只动一个物体 |
| 飘太高 / 出去画了 | 按"物体顶面 ≤ 层高 − 0.1m"反算升幅下调 | 竖屏最容易顶穿 |
| 椅子撞腿了 | 椅起飞延后 +0.2s，并加水平让位 0.3~0.5m | 见 03 号时序规范 |
| 桌子和设备打架 | 设备先升 1.3m 悬停，桌体延后 2~3s | 因果句写进提示词 |
| 收尾太急 | 尾段加 0.4~0.6s 减速静止 | 相机速度曲线末端走缓 |
| 镜头晃 / 别抖 | 查关键帧插值是否回弹，改 LINEAR + 单调 | 一阶差分符号必须不变 |
| 人转过来了 | 锁朝向：全程背向/侧背向、不回头；反向词补转身回头 | 这条只能靠提示词锁，白模不管 |
| 房间也在飘 | 只对主体组做 z 位移，墙地窗静止 | 常见父级关系写错 |
| 改竖屏 | 画幅 9:16，重算安全框与升幅 | 竖屏安全框更窄，先降半径 |

**一次只改一项**，改完立刻出片。同时改三项以上，用户看不出是哪项起了作用。

## 5. 版本管理

- 文件命名：`previs_v1_横屏10s.mp4`、`previs_v2_半径收紧.mp4`、`previs_v3_失重延后.mp4`。
- 命名禁用点号（`v1.0` 这类在部分平台不合规），用 `v10` 形式。
- 每版必须写 1 行变更说明 + 是否重跑四项校验；工程文件同名，保证任何一版都能回到现场。
- 只有最后一版进阶段 ⑤ 写词；中间版本不写词。

## 6. 与 Seedance 2.5（及其他视频模型）对接口径

交付时把这两样东西一起交出去，并说清各自角色：

| 素材 | 在视频模型里的角色 | 提示词里怎么写 |
|---|---|---|
| 白模预演视频 | **运动 / 机位 / 时序参考**，不参与画面质感 | `@视频1：相机运动与物体时序参考（白模），不参考画面风格、材质、光影` |
| 用户参考图 | **画面唯一参考**：造型、配色、光影、质感 | `@图片1：画面唯一参考` |
| 六栏目提示词 | 把参考视频的运动翻译成模型能读的语言 | 每段带秒数 + 起止机位 + 半径 + 仰角 + 注视点 |

实操要点：

1. **时长对齐**：白模视频时长 = 目标成片时长（5s / 10s），不要让模型自己猜节奏。
2. **分辨率适中**：导出 480P / 960×540 即可，运动信息已经足够，文件小上传快。
3. **首句强调复刻**：提示词第一句写"严格复刻参考视频的相机运动与物体起飞顺序"，模型忽略参考视频时这句是最后一道保险。
4. **运镜拆段**：把白模时间轴按 2~3 秒切成段，一段一句运镜描述，别写成一整段形容词。
5. **画面与运动分家**：模型把白模的灰模质感带进成片，说明【参考】里"非画面参考"没写死，回阶段 ⑤ 修词，不要靠加反向词硬压。
6. **平台限制**：某些平台限制参考视频数量或时长，超限就只传白模（运动优先）+ 提示词里写清画面。

## 7. 对话层禁止事项

- 不向用户解释极角、NDC、穿模对数、AABB 这类术语，除非用户主动问"你们怎么验的"。
- 不在用户看片确认前写提示词（写了也大概率废稿）。
- 不一次抛 5 个问题，不把参数表丢给用户填空。
- 用户说"随便你 / 你看着办"时，用默认值直接出第一版，再让他看片挑毛病。
- 不用"注意不要穿模"这种否定句写词，用因果顺序句（见 04 号规范）。
